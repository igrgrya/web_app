# Funds Lab: весь сервис на одном бесплатном хостинге

## Опубликованный сервис

**Адрес: https://fundslab.alwaysdata.net/**. Полный сайт, FastAPI и PostgreSQL
работают в одном аккаунте **fundslab**, тариф подтверждён в панели:
**Free, 0 €, 1 ГБ SSD, 256 МБ RAM, 0,25 CPU**.

- Лабораторная №2: https://fundslab.alwaysdata.net/xml.html
- Лабораторная №3: https://fundslab.alwaysdata.net/db.html
- Документация API: https://fundslab.alwaysdata.net/docs
- Проверка подключения: https://fundslab.alwaysdata.net/api/health

На хостинге установлены Python 3.12 и PostgreSQL **17**. Восстановлены все
15 таблиц; количества строк совпадают с исходной базой, включая 18 инструментов
и 558 снимков цен. Пользователь `fundslab_app` после импорта переключён на
**read only**; проверено SQL-запросом, что SELECT разрешён, INSERT/UPDATE/DELETE
запрещены. HTTP автоматически переводится на HTTPS.
Временный SSH-ключ переноса удалён из аккаунта после успешной приёмки.

Приложение занимает около 72 МиБ файлов; база — около 9 МБ. На опубликованном
сервисе прошли **108 HTTP-проверок и 58/58 исходных проверок БД/API**.

| InfinityFree | Нет | PHP и MySQL/MariaDB; FastAPI/Python и PostgreSQL не поддерживаются |
| Render Free | Не подходит для постоянной бесплатной БД | Бесплатный PostgreSQL истекает через 30 дней; Aiven нарушает требование одного хостинга |

переноса существующего сервиса это сложнее и создаёт риск потерять требования лабы.

## Что находится в ZIP

`deployment/funds-lab-full.zip` распаковывается в папку `funds-lab/`:

- `web/` — полный текущий сайт: главная, новости, биржи, история, материалы
  новичку, глоссарий, риски, ссылки, контакты, о проекте, поиск, форум,
  гостевая книга, сервисы, XML/XSLT, обмен данными RSS (лаб. №4) и
  лабораторная №3 `/db.html`;
- `backend/` — настоящий FastAPI + SQLAlchemy: запросы Q1–Q5 (лаб. №3) и
  обмен данными — RSS/CSV/ASCII+XML, внешние фиды, импорт (лаб. №4);
- `db/migration.sql` — полный снимок **всех 15 таблиц** локального PostgreSQL
  на момент упаковки; не только четыре таблицы каталога;
- `db/schema.sql`, `seed.sql`, `seed_history.sql` — исходная схема и учебные данные;
- `frontend/` и `static/` — исходники предыдущего React-интерфейса и генератора;
- `deploy/` — установка, настройка подключения, импорт, запуск и проверка;
- `MANIFEST.json` — контрольные суммы файлов; `Dockerfile` — запасной
  контейнерный запуск всего сервиса, а не одной лабораторной.

В ZIP нет `.git`, `.env`, паролей, Windows-окружений Python, node_modules,
учётных данных Sites или внешних подключений к Render/Aiven/D1.
Снимок БД содержит данные проекта: архив не следует публиковать как файл сайта.

Гостевая книга, форум, опрос, подписки и счётчик в текущей версии сайта
используют **localStorage браузера**, как и до переноса. Это сохранено.
Перенос хостинга не превращает их в общую серверную базу. Данные localStorage
старого домена браузер автоматически новому домену не передаёт.
Погода и курсы валют по-прежнему запрашиваются у поставщиков данных;
это внешние информационные API, а не дополнительный хостинг частей проекта.

## Публикация: один раз

1. [Зарегистрировать Free](https://www.alwaysdata.com/en/register/?p=2012),
   подтвердить почту. В панели убедиться, что выбран именно **Free 0 €**,
   а не пробный Plus на 30 дней. Имя аккаунта определяет адрес сайта.
2. **Environment → Python**: Python **3.12**.
   **Databases → PostgreSQL**: создать базу `ИМЯ_funds` и пользователя
   `ИМЯ_app`. Версию PostgreSQL предоставляет хостинг (в fundslab — **17**);
   восстановление снимка из локальной PostgreSQL 18 в PostgreSQL 17 проверено.
   На время первичного импорта нужны права записи только в эту новую базу;
   после импорта переключить пользователя приложения на **read only**.
   Пароль БД вводится только в скрытом запросе установщика.
3. Загрузить ZIP по SFTP в домашнюю папку аккаунта. Параметры подключения —
   **Remote access → SSH/SFTP**; использовать точное имя сервера из панели.
   Затем в SSH распаковать архив:

   ```sh
   python -m zipfile -e funds-lab-full.zip .
   cd funds-lab
   sh deploy/install.sh
   .venv/bin/python deploy/configure.py
   .venv/bin/python deploy/init_db.py
   ```

   `configure.py` спросит имя аккаунта, имя БД, пользователя (`ИМЯ_app`) и пароль.
   Сохранит подключение в `backend/.env` с правами 600; заполнит домен в
   контактах, sitemap и robots. `init_db.py` восстановит все таблицы из снимка
   в одной транзакции и **откажется работать на непустой базе**.
4. **Web → Sites**: изменить стартовый сайт аккаунта или создать сайт с его
   штатным адресом `ИМЯ.alwaysdata.net`:

   | Поле | Значение |
   | --- | --- |
   | Type | **User program** |
   | Working directory | `/home/ИМЯ/funds-lab` |
   | Command | `/home/ИМЯ/funds-lab/.venv/bin/python /home/ИМЯ/funds-lab/deploy/start.py` |

   Программа сама читает обязательные `$IP` и `$PORT` хостинга, включая IPv6.
   Не выбирать WSGI и не запускать приложение как отдельную службу Services.
5. Включить HTTPS в настройках сайта. Проверить с сервера или локально:

   ```sh
   .venv/bin/python deploy/check.py https://ИМЯ.alwaysdata.net
   ```

   Главная — `/`, все разделы — на том же адресе, БД — `/db.html`,
   API — `/api/…`, Swagger без внешнего CDN — `/docs`.
   `/lab3/` перенаправляет на `/db.html`.
6. Повторно проверить **именно новый домен** с российских узлов.
   Пока эти действия не выполнены, архив подготовлен, но перенос не завершён.

## Лабораторная работа №4: обмен данными (RSS, CSV, ASCII+XML)

Маршруты `backend/app/lab4.py`, страница `/rss.html` (интерактив) и серверная
страница `/lab4/combined.html`. Отчетные форматы:

- `GET /api/rss` и `GET /rss.xml` — RSS 2.0-лента из таблицы `news` (XML-файл);
- `GET /api/export/news.csv` — CSV «;» со списком полей (UTF-8 BOM, открывается в Excel);
- `GET /api/export/news.tagged.txt` — ASCII-файл, оконтуренный XML-тегами (тело в CDATA);
- `GET /api/lab4/sources` — каталог внешних RSS-источников (РБК, Lenta, Интерфакс, ТАСС);
- `GET /api/lab4/external-rss?url=|source=` — скачать и разобрать внешний RSS (кэш 10 мин);
- `GET /api/lab4/combined-news?url=|source=&limit=` — объединенные новости (БД + внешний фид);
- `GET /lab4/combined.html` — страница «Объединенные новости» из подготовленного шаблона;
- `POST /api/lab4/import?url=|source=&limit=` — загрузка внешних новостей в таблицу `imported_news`;
- `GET /api/lab4/imported` — просмотр импортированного.

Таблица `imported_news` создается приложением сама (идемпотентный
CREATE TABLE при первом обращении), ручная миграция БД при обновлении сайта
не требуется; в `db/schema.sql` её DDL добавлен для новых установок.

### Права на запись для импорта (обязательно перед показом преподавателю)

Пользователь приложения `fundslab_app` на опубликованном сервисе переключен
в **read only** — этап «загрузить полученные данные в СУБД» лабораторной №4
без дополнительных прав завершится ошибкой прав. Решение — один раз выдать
права только на таблицу импорта, не снимая read-only с остальных таблиц:

1. В панели alwaysdata откройте **Databases → PostgreSQL**, выберите базу
   `fundslab_funds` и веб-консоль (**Console**), либо подключитесь `psql`
   через **Remote access** (данные подключения — в панели).
2. Выполняйте SQL **от имени администратора базы** (владельца аккаунта),
   не `fundslab_app`:

   ```sql
   CREATE TABLE IF NOT EXISTS imported_news (
       id            SERIAL PRIMARY KEY,
       source_url    TEXT NOT NULL,
       source_title  TEXT NOT NULL DEFAULT '',
       guid          TEXT NOT NULL,
       title         TEXT NOT NULL,
       link          TEXT NOT NULL DEFAULT '',
       summary       TEXT NOT NULL DEFAULT '',
       published_at  TIMESTAMP,
       imported_at   TIMESTAMP NOT NULL DEFAULT now(),
       UNIQUE (source_url, guid)
   );
   GRANT SELECT, INSERT ON imported_news TO fundslab_app;
   GRANT USAGE, SELECT ON SEQUENCE imported_news_id_seq TO fundslab_app;
   ```

3. Проверка: на https://fundslab.alwaysdata.net/rss.html нажать
   «Импортировать 10 свежих записей фида» — статус должен показать
   «вставлено 10, дубликатов пропущено 0» (при повторе — «вставлено 0»).

Если права не выданы, приложение не падает: `POST /api/lab4/import` отвечает
503 с пояснением, список импортированного показывает уведомление, остальные
разделы лабораторной №4 работают.

Внешние источники бывают недоступны (например, некоторые блокируют серверных
клиентов) — в этом случае API отдаёт понятную ошибку, а страница объединенных
новостей показывает только новости БД с уведомлением.

### Права на запись для ввода данных (CRUD) — правка к лабораторной №4

Раздел «Ввод данных» приложения (`/db.html`) добавляет и изменяет инструменты
и котировки: записи идут в таблицы `instruments` и `price_snapshots` (полный
CRUD — нужны INSERT, UPDATE и DELETE). Пользователь приложения `fundslab_app`
находится в read only, поэтому без прав форма вернёт уведомление 503.
Как и для импорта, права выдаются разово и только на эти две таблицы.

**Шаг 0 — ключ защиты записи (обязателен ДО выдачи прав).** Операции записи
защищены общим ключом сервера: без ключа API отвечает 401, и после GRANT
писать через API смогут только те, у кого есть ключ. Задайте переменную
окружения `FUNDS_ADMIN_KEY` программе:

1. В панели alwaysdata откройте **Web → Sites → (ваш сайт) → Edit** и найдите
   раздел переменных окружения (**Environment** / «Переменные окружения»)
   у программы запуска.
2. Добавьте переменную `FUNDS_ADMIN_KEY` со случайным значением, например
   сгенерированным командой `openssl rand -hex 16` (или любым генератором
   паролей). Сохраните и перезапустите сайт (**Save → Restart**).
3. Это же значение потом вводится в поле «Ключ записи» на `/db.html`
   (сохраняется в браузере и передаётся в заголовке `X-Admin-Key`).
4. Проверка: откройте «Сведения о БД» — строка про защиту записи должна
   смениться с «защита записи выключена» на «запись защищена ключом».

После ключа выдайте права на таблицы:

1. В панели alwaysdata откройте **Databases → PostgreSQL**, выберите базу
   `fundslab_funds` и веб-консоль (**Console**).
2. Выполняйте SQL **от имени администратора базы** (владельца аккаунта),
   не `fundslab_app`:

   ```sql
   GRANT SELECT, INSERT, UPDATE, DELETE ON instruments, price_snapshots TO fundslab_app;
   GRANT USAGE, SELECT ON SEQUENCE instruments_id_seq, price_snapshots_id_seq TO fundslab_app;
   ```

3. Проверка в той же консоли (должно вернуть `t` для обеих таблиц):

   ```sql
   SELECT has_table_privilege('fundslab_app', 'instruments', 'INSERT') AS inst,
          has_table_privilege('fundslab_app', 'price_snapshots', 'INSERT') AS snap;
   ```

4. Проверка в приложении: откройте https://fundslab.alwaysdata.net/db.html,
   введите ключ в поле «Ключ записи» и нажмите «Сохранить ключ» — в разделе
   «Сведения о БД» у строк `instruments` и `price_snapshots` должны появиться
   ✅ по всем операциям (добавление/изменение/удаление/секвенция — раздел
   читает права напрямую из СУБД, страницу перезагрузить после выдачи прав).
   Затем добавить тестовый инструмент и котировку в разделе «Ввод данных»;
   после демонстрации их можно удалить кнопкой 🗑 (удаление инструмента
   стирает и его историю цен — об этом предупреждает диалог подтверждения).

Если права не выданы, приложение не падает: операции ввода отвечают 503
с пояснением (то же поведение, что у импорта), над формами показывается
предупреждение о read-only, а демонстрацию ввода можно выполнить на локальной
копии приложения. Раздел «Сведения о БД» работает всегда — он читает
метаданные СУБД без записи.

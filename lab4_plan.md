# План лабораторной работы №4 — «Организация обмена данными между приложениями»

## Что требует методичка (lab_instructions.md, ЛР №4)

**Цель** — получение навыков обмена данными в Интернет.

**Этапы:**
1. изучить протокол передачи новостных данных RSS;
2. разработать структуру формата передачи на основе XML (для новостей в формате RSS);
3. доработать приложение по извлечению из БД информации в структуре формата обмена;
4. загрузить полученные данные в другую СУБД **или** произвести прикладную обработку файла.

**Форма отчетности:** приложения, запускаемые с web-сайта (созданного в ЛР №1),
представляющие данные в различных форматах для использования другими приложениями:
- ASCII через разделитель со списком полей;
- XML-файл;
- ASCII-файл, оконтуренный XML-тегами.

**Схема обмена (рис. 2):** Внешний RSS-файл (из Интернета) + БД «Новости» (1 лаб. раб.)
→ PHP-приложение (написать) → HTML-страница «Объединенные новости» на сайте студента.

## Как этапы ложатся на проект (FastAPI вместо PHP — стек ЛР №3)

| Этап методички | Реализация |
|---|---|
| 1. Изучить RSS | Раздел «Формат RSS 2.0» на странице rss.html: структура канала и элемента |
| 2. Структура формата на основе XML | RSS 2.0-лента из БД + описание формата обмена на странице |
| 3. Извлечение из БД в формат обмена | `GET /api/rss`, `GET /rss.xml` — лента из таблицы `news`; экспортные эндпоинты |
| 4. Обработка / загрузка в СУБД | Прикладная обработка: страница «Объединенные новости» (БД + внешний RSS); загрузка внешних новостей в таблицу `imported_news` |
| Форма отчетности: CSV | `GET /api/export/news.csv` — `;`-разделитель, первая строка — список полей, UTF-8 BOM (открывается в Excel) |
| Форма отчетности: XML-файл | `GET /api/rss` (=`/rss.xml`) — RSS 2.0 из БД |
| Форма отчетности: ASCII в XML-тегах | `GET /api/export/news.tagged.txt` — плоский дамп таблицы, тело новости в `<![CDATA[...]]>` (сырой ASCII внутри XML-оболочки) |
| Рис. 2: внешний RSS | `GET /api/lab4/external-rss?url=` — серверная загрузка (urllib, таймаут 10 с, лимит 2 МБ) и разбор RSS 2.0/Atom (stdlib ElementTree) |
| Рис. 2: БД + внешний → страница | `GET /api/lab4/combined-news` (JSON) и `GET /lab4/combined.html` (готовая HTML-страница из подготовленного шаблона) |
| Задел «другая СУБД» | `POST /api/lab4/import` — внешний RSS → таблица `imported_news` (idempotent CREATE TABLE IF NOT EXISTS, дедуп по (source_url, guid)) |

## Ключевые решения

- **Отдельный модуль `backend/app/lab4.py`** (APIRouter): лаба №4 не смешивается с
  запросами Q1–Q5 лабы №3; в `main.py` — только include_router и маршрут `/rss.xml`.
- **Без новых зависимостей**: urllib + xml.etree из stdlib — бандл для alwaysdata
  остается с прежними requirements (fastapi/uvicorn/SQLAlchemy/psycopg2).
- **Кэш внешних фидов в памяти** (TTL 10 мин) + отдача устаревшей копии при ошибке
  загрузки: страница не падает, если источник недоступен (проверено: interfax.ru и
  tass.ru блокируют python-клиент с некоторых сетей — ошибка показывается явно).
- **Список источников**: РБК (по умолчанию), Lenta.ru, Интерфакс, ТАСС + произвольный URL.
- **Дедуп объединенных новостей** — по нормализованному заголовку; сортировка по дате
  по убыванию; каждая запись помечена источником («БД funds_lab» / название фида).
- **`imported_news`** — DDL и в db/schema.sql (для новых установок), и ленивый
  `CREATE TABLE IF NOT EXISTS` при первом импорте (для уже развернутого инстанса
  alwaysdata миграция руками не нужна).
- **pubDate**: даты БД наивные (TIMESTAMP без TZ) — считаем их московским временем
  (+03:00) и форматируем по RFC-822 (email.utils.format_datetime).
- **Ссылки в ленте** строятся из `request.base_url` (на alwaysdata за прокси —
  proxy_headers=True), поэтому RSS валиден и локально, и на проде.
- **Статический `site/rss.xml`** генерируется build.mjs из seed-новостей (GitHub Pages),
  а на проде `/rss.xml` перехватывается маршрутом FastAPI и отдает динамическую ленту
  из БД: адрес один, содержимое всегда из БД там, где есть приложение.
- **Страница rss.html** — в двух вариантах по сложившейся схеме:
  - `site/rss.html` (генерируемый, GitHub Pages) — описание лабы, форматы, ссылки на
    развернутое приложение (как site/db.html для ЛР №3);
  - `hosting/public/rss.html` (развертываемая) — та же теория + интерактив: выбор
    источника, загрузка внешнего RSS, объединение, импорт в БД, предпросмотр форматов.
- **JS/CSS интерактива** — `backend/app/static/lab4.js` и `lab4.css` (раздаются по
  `/static/...` и попадают в бандл автоматически вместе с `backend/app/`).
- **Пункт меню не переименовываем** («RSS», не «RSS (лаб. №4)»): меню обязано
  оставаться в одну строку (раунд 5 правок), страница носит номер лабы в заголовке.

## Эндпоинты лабы №4

| Маршрут | Что отдает |
|---|---|
| `GET /api/rss`, `GET /rss.xml` | RSS 2.0 из таблицы `news` (XML-файл) |
| `GET /api/export/news.csv` | CSV `;` со списком полей (ASCII через разделитель) |
| `GET /api/export/news.tagged.txt` | ASCII-файл, оконтуренный XML-тегами (CDATA) |
| `GET /api/lab4/sources` | Список рекомендуемых внешних RSS-источников |
| `GET /api/lab4/external-rss?url=` | Разобранный внешний фид (JSON) + кэш |
| `GET /api/lab4/combined-news?url=&limit=` | Объединенные новости: БД + внешний фид |
| `GET /lab4/combined.html` | Страница «Объединенные новости» (шаблон + данные) |
| `POST /api/lab4/import?url=` | Загрузка внешних новостей в `imported_news` |
| `GET /api/lab4/imported` | Просмотр импортированных новостей |

### Этап 2. Генерация catalog.xml — `static/build.mjs`

1. Написать функцию `buildCatalogXml(instruments, exchanges, sectors)`, возвращающую
   строку XML. Экранирование — существующим хелпером `esc()` из build.mjs
   (он экранирует `& < > " '` — подходит и для текста, и для атрибутов).
2. Подключить её в `main()`: `writeOut('catalog.xml', buildCatalogXml(instruments, exchanges, sectors))`.
3. Сборка должна быть детерминированной: никаких дат генерации внутри XML.

Целевая структура `site/catalog.xml` (18 элементов `instrument`, ниже — образец):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalog>
  <instrument id="1" ticker="SBER">
    <name>Сбербанк</name>
    <type>stock</type>
    <exchange>MOEX</exchange>
    <sector>Финансы</sector>
    <price currency="RUB">285.5</price>
    <changePercent>1.2</changePercent>
    <volume>15000000</volume>
  </instrument>
  <!-- ...ещё 17 записей... -->
</catalog>
```

`exchange` и `sector` — код биржи и название сектора (lookup по `exchangeId`/`sectorId`),
а не id: XML должен читаться человеком без обращения к сайту.

### Этап 3. XSL-шаблон — новый файл `static/src/catalog.xsl`

1. `xsl:stylesheet version="1.0"` (браузерный `XSLTProcessor` — это XSLT 1.0, без EXSLT).
2. Параметры шаблона (все задаются из страницы через `setParameter`):

| Параметр | Значения | Назначение |
| --- | --- | --- |
| `sortKey` | `ticker` \| `name` \| `price` \| `changePercent` \| `volume` | Поле сортировки |
| `sortDir` | `ascending` \| `descending` | Направление |
| `filterExchange` | `''` \| `MOEX` \| `NASDAQ` \| `NYSE` | Фильтр по бирже |
| `filterType` | `''` \| `stock` \| `etf` | Фильтр по типу |
| `filterSector` | `''` \| название сектора | Фильтр по сектору |
| `query` | подстрока | Поиск по `name` или `ticker`, без учёта регистра |

3. Логика шаблона:
   - сначала `<xsl:variable name="filtered" select="..."/>` с предикатами всех трёх
     фильтров и поиска (регистронезависимость — через `translate()` для латиницы
     и кириллицы, приведение и строки, и `$query` к нижнему регистру);
   - из `$filtered` считаем `count($filtered)` для счётчика «Показано N из 18»;
   - сортировка: `xsl:choose` по `$sortKey` с пятью ветками, в каждой —
     `<xsl:apply-templates select="$filtered">` со своим `<xsl:sort .../>`
     (`data-type="number"` для price/changePercent/volume, `text` для ticker/name,
     `order="{$sortDir}"` — AVT в `order` разрешён спецификацией XSLT 1.0);
   - вывод: **вся таблица целиком** формируется XSL — `<table class="data-table">`
     с `<caption>` и `<thead>` (Тикер, Название, Тип, Биржа, Сектор, Цена, Изм. за день,
     Объём торгов) и строками `<tbody>`.
4. Форматирование в ячейках:
   - цена: число + валюта из атрибута `currency` (RUB → «₽», USD → «$»);
   - изменение: знак «+»/«−» и класс `change-up` / `change-down` для окраски;
   - объём: сокращённо, например «15,0 млн» (деление в XSL и формат через `format-number`).
5. Стили: если в `static/src/styles.css` нет классов `change-up`/`change-down` —
   добавить (зелёный/красный цвет текста, в тон существующей палитре).
6. В `build.mjs` рядом с копированием `styles.css` добавить
   `copyFileSync(join(SRC, 'catalog.xsl'), join(OUT, 'catalog.xsl'))`.

### Этап 4. Страница каталога — `xmlPage()` в `build.mjs` + `initCatalog()` в `static/src/app.js`

**Разметка (build.mjs, функция `xmlPage()`):** убрать тексты заглушки, сформировать:

- `<h1>` «Каталог инструментов», lead-абзац: данные хранятся в XML-файле, вид
  страницы формируется XSLT-преобразованием прямо в браузере;
- панель управления (обычная `<form onsubmit="return false">` в стиле сайта):
  - select «Сортировка»: по тикеру / названию / цене / изменению / объёму;
  - select «Направление»: по возрастанию / по убыванию;
  - select «Биржа»: все / MOEX / NASDAQ / NYSE;
  - select «Тип»: все / акции / ETF;
  - select «Сектор»: все / 5 секторов из seed;
  - input search «Поиск по названию или тикеру»;
  - кнопка «Сбросить» (type=reset или button);
- `<div id="catalog-output">` — контейнер, куда вставляется результат трансформации;
  до загрузки внутри «Загрузка каталога…»;
- абзац «Исходные данные»: ссылки `catalog.xml` и `catalog.xsl`
  (`target="_blank" rel="noopener"`) — преподаватель должен видеть исходники;
- `<p id="catalog-fallback" hidden>` — сообщение «Браузер не поддерживает XSLT».

**Клиентская логика (app.js, новая функция `initCatalog()`):**

1. Выйти, если на странице нет `#catalog-output` (тот же паттерн, что у остальных
   `init*`; вызвать её из общего инициализатора рядом с остальными).
2. `fetch('catalog.xml')` и `fetch('catalog.xsl')` → `DOMParser` c типом
   `'application/xml'`; при `parsererror` — вывести сообщение об ошибке в контейнер.
3. `const processor = new XSLTProcessor(); processor.importStylesheet(xslDoc);`
4. Функция `render()`: прочитать текущие значения контролов →
   `processor.setParameter(null, 'sortKey', ...)` (и остальные параметры) →
   `processor.transformToFragment(xmlDoc, document)` → заменить содержимое
   `#catalog-output`.
5. Слушатели `change` на всех select и `input` (с лёгким debounce) на поле поиска,
   обработчик сброса (вернуть дефолты и вызвать `render()`).
6. Деградация: если `typeof XSLTProcessor === 'undefined'` — показать
   `#catalog-fallback` и не ронять остальную страницу.

Нюанс: `fetch` не работает с протокола `file://` — локальная проверка только через
HTTP-сервер (раздел 6, п. 4).

## 8. Хостинг

### 8.1. «На GitHub можно хостить только статические сайты — это так?»

Да, в основном так: GitHub Pages отдаёт только статические файлы и не исполняет код
на сервере (PHP, Python, Node, `.htaccess` — недоступны). Но «статика» — это не
только HTML: XML, XSL, CSS, JS, JSON, картинки Pages отдаёт как обычные файлы.
Поэтому выбранный вариант лаб. №2 (XML + XSL, трансформация в браузере) полностью
укладывается в GitHub Pages — хостинг менять не нужно. Лимиты Pages для учебного
сайта с запасом: размер сайта ≤ 1 ГБ, ~100 ГБ трафика в месяц, мягкий лимит
10 сборок в час.

### 8.2. Как хостится сайт сейчас (менять ничего не надо)

1. Все правки — только в `static/` и `frontend/src/data/seed.js`, затем
   `node static/build.mjs` (обновится `site/`).
2. Коммит в `dev`, push; PR `dev → main` (сливает владелец).
3. Workflow `.github/workflows/pages.yml` при пуше в `main` сам заливает папку
   `site/` на GitHub Pages (Settings → Pages, source: GitHub Actions).
4. URL: <https://igrgrya.github.io/web_app/>.

### 8.3. Запасная ветка: если преподаватель потребует именно PHP

Тогда понадобится внешний PHP-хостинг (основной сайт остаётся на Pages, с страницы
каталога ставится ссылка «PHP-вариант»).

1. **InfinityFree** (infinityfree.com) — основной бесплатный вариант: PHP 8, без
   рекламы, панель + FTP. Шаги: регистрация → Create Account → бесплатный поддомен →
   File Manager (или FileZilla по FTP) → загрузить `catalog.php`, `catalog.xml`,
   `catalog.xsl` в `htdocs` → сайт доступен по выданному URL. Нюанс: доступность
   из РФ проверять сразу, возможны ограничения.
2. **alwaysdata.com** — альтернатива: бесплатный тариф 100 МБ с PHP, веб-панель, SSH.
3. Российский запасной (стабильный URL, доступный из РФ без VPN): пробный период
   Beget / Timeweb, далее ~150–200 ₽/мес.
4. `catalog.php`: читает XML через `DOMDocument`, применяет XSL через PHP-класс
   `XSLTProcessor`, параметры сортировки/фильтров берёт из `$_GET`. Перед выкладкой
   проверить в `phpinfo()`, что включены расширения `dom` и `xsl` (на shared-хостингах
   обычно да).

## 9. Правила исполнителю

1. `site/` генерируется — **руками не править**; всё через `static/`, `static/src/`
   и `frontend/src/data/seed.js` с последующей пересборкой.
2. Меню (`NAV` в build.mjs) не трогать: выверено по ширине в одну строку, правки
   ломают вёрстку (было 5-й раунд замечаний преподавателя).
3. Правила git — из `CLAUDE.md` (раздел 7 выше — краткая выжимка).
4. Цены, объёмы и даты в каталоге — условные; реальные котировки не искать,
   API не подключать.
5. Новые npm-пакеты не добавлять: сборка на чистом Node без зависимостей.
6. Стиль кода — как в существующих файлах (русские комментарии, те же приёмы,
   хелпер `esc()` для экранирования).
7. `XSLTProcessor` поддерживают все актуальные Chrome/Edge/Firefox/Safari —
   этого достаточно; fallback из этапа 4 всё равно обязателен.
8. После каждого этапа прогонять соответствующие пункты раздела 6.

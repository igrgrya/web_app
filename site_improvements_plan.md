# План улучшений сайта Funds Lab (для исполнителя)

Дата: 2026-11-06. Принцип плана: **никакого нового функционала** — только
лучшая подача того, что уже есть (API лаб. №3 и №4, данные seed, генератор
сайта). Все задачи выполняются на существующих эндпоинтах и данных.

Прод: https://fundslab.alwaysdata.net (FastAPI раздаёт сайт + API + БД).
GitHub Pages публикует собранную папку `site/` из `main`.

## Правила для исполнителя (обязательные)

1. `site/` генерируется: править только `static/` (build.mjs, src/), затем
   `node static/build.mjs`. Напрямую `site/*.html` не редактировать.
2. `hosting/public/` — страницы прод-версии. После правок страниц лаб. №3
   держать копии `hosting/public/static/{app.js,styles.css,index.html}`
   синхронными с `backend/app/static/` (бандл берёт app.js из backend).
   При правке `lab4.js`/`lab4.css` поднимать версию `?v=N` в `rss.html`.
3. После каждой задачи — прогон приёмки, всё зелёное:
   - `backend/tests/acceptance.py` (58 проверок; при запуске сервера с
     `FUNDS_PUBLIC_DIR=hosting/public` передавать `LAB3_UI_PATH=/db.html`),
   - `backend/tests/lab4_acceptance.py` (41 проверка),
   - `backend/tests/history_regression.py`.
   В Git Bash прокидывайте пути с `MSYS_NO_PATHCONV=1`.
4. Git: работа в `dev`, коммит после каждой задачи, push в `origin/dev`.
   `main` — только через PR (делает владелец).
5. Деплой на alwaysdata — владелец (пересборка бандла `deploy/build_bundle.py`
   + заливка). Исполнитель до деплоя не доходит.

## Уже сделано 2026-11-07 (раунд 2: закрытие ревью CRUD — 6 пунктов)

Ревью раунда «ввод данных» нашло 6 замечаний (2×P1, 4×P2); все закрыты:

1. **Авторизация записи (P1):** все операции CRUD требуют заголовок
   `X-Admin-Key` со значением переменной `FUNDS_ADMIN_KEY` сервера (ключ не
   задан — запись открыта, но «Сведения о БД» честно предупреждают «защита
   выключена»; шаг 0 в чек-листе DEPLOY_ALWAYSDATA.md — задать ключ ДО GRANT).
   В UI — поле «Ключ записи» (localStorage), 401 показывается по-человечески.
   Проверки: backend/tests/write_auth_check.py (12 проверок, второй инстанс
   с ключом) + UI-прогон 401→ключ→201.
2. **Гонка правки снимка (P1):** правка привязана к паре «инструмент + дата»,
   устаревший ответ после смены инструмента отбрасывается (счётчик),
   PUT идёт по зафиксированной паре; проверено браузером с управляемой
   задержкой ответа.
3. Явный null у обязательных полей → 422 с пояснением (был IntegrityError 500);
   необязательные поля null-ом очищаются.
4. Строки из одних пробелов → 422; цена — Decimal с проверкой «не больше
   4 знаков» (0.00001 больше не превращается в 0 на стороне БД), минимум
   фактически 0.0001.
5. После любой записи перерисовываются график и карточка; при удалении
   инструмента, выбранного на графике, панель очищается.
6. «Сведения о БД» показывают права по операциям (SELECT/INSERT/UPDATE/
   DELETE/секвенция отдельно для instruments и price_snapshots), режим
   read-only транзакций (default_transaction_read_only) и список недостающих
   прав; can_write = честный флаг полного CRUD. Частичные права проверены
   временной ролью INSERT-only (backend/tests/read_only_check.py, 503 + ⛔).

Приёмка: acceptance.py 110/110, lab4 41/41, history_regression, auth 12/12,

## P1 — заметно на защите, дёшево

### 1. Клик по столбцу диаграммы секторов фильтрует каталог
Q3 и Q1 уже связаны данными. В `backend/app/static/app.js` в конфиг Chart.js
`sectorsChart` добавить `onClick: (evt, elements) => { … }`: по индексу
элемента взять `rows[i].sector`, выставить `fSector.value` (опция могла не
существовать, если фильтры ещё не заполнены — тогда дождаться `loadCatalog`),
вызвать `runSearch()` и проскроллить к `#catalog-section`.
Приёмка: клик по столбцу «Нефть и газ» → в каталоге только этот сектор,
плашка фильтра обновлена.

### 2. Deep-link графика: `#instrument=GAZP&days=90`
Сейчас выбранный инструмент живёт только в памяти страницы. Добавить в
`app.js`: при загрузке разбирать `location.hash`, находить тикер через уже
загруженный `fillInstrumentPicker` (у опций есть тикер), ставить
`chartInstrument.value` и `chartDays.value`, вызывать `renderPriceChart()`;
при `openPriceChart`/смене селектов — `history.replaceState(null, "", …)`.
Приёмка: ссылка с хэшем открывает график конкретного инструмента; хэш
обновляется при кликах по строкам каталога. На защите можно показать график
одной ссылкой.

### 3. Мини-статистика в карточке инструмента
В `renderPriceChart` уже приходит вся серия `series` (Q5б). Посчитать на
клиенте min/max/среднюю цену за выбранный период и дописать строку в
`instrumentCard` (например: «За период: мин 82,10 · макс 96,40 · средн. 89,03»).
Приёмка: при смене периода цифры пересчитываются, формат ru-RU.

### 4. Видимые ошибки Q3/Q4 (сейчас — только console.error)

`<p class="status">` в секциях `#sectors-section`/`#movers-section`

Приёмка: остановить БД → в секциях виден русский текст ошибки, не пустота.

### 5. Блок «Внешние новости рынка» на странице Новости
`news.html` показывает только 7 новостей из seed. Под таблицей добавить
блок, который клиентски зовёт уже существующий
`GET /api/lab4/external-rss?source=rbc` и рендерит 5 свежих заголовков
(шаблон разметки — как в `renderExternalItems` из lab4.js). Блок скрывать
при ошибке источника. Реализация: небольшой скрипт в `static/build.mjs`
(генерация news.html) или общий модуль в `static/src/app.js`, подключённый

Приёмка: на проде под таблицей новостей виден блок с внешними заголовками;
на GitHub Pages страница выглядит как раньше.

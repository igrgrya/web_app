# Публикация лабораторной №3 на Koyeb — полностью бесплатный хостинг

В отличие от Amvera, free-план Koyeb не имеет срока действия: 1 веб-сервис +
1 serverless PostgreSQL бесплатно навсегда, регистрация по GitHub/e-mail без
банковской карты, публичный домен `*.koyeb.app`. Приложение работает как
полноценный веб-сервис: настоящий FastAPI + PostgreSQL, UI и запросы Q1–Q5.

Состав деплоя (добавляется к пакету Amvera):
- `Dockerfile` — образ приложения: python:3.12-slim, зависимости из
  `backend/requirements.txt`, uvicorn слушает `${PORT:-8000}`;
- `.dockerignore` — контекст сборки без node_modules, скриншотов и отчётов;
- `DEPLOY_KOYEB.md` — этот файл.

Код приложения и сид-скрипт не менялись:
- `backend/app/database.py` сам приводит `postgres://`/`postgresql://` из
  Koyeb к `postgresql+psycopg2://`, а `pool_pre_ping=True` переживает
  засыпание serverless-БД;
- `db/seed_amvera.py` универсален — принимает URL подключения аргументом
  (слово «amvera» в имени историческое, скрипт подходит для любой базы).

Особенности free-плана (норма для всех бесплатных тарифов):
- сервис засыпает после ~1 часа без трафика и просыпается на первом запросе
  за 1–5 секунд (light sleep); отключить это на free-тарифе нельзя;
- PostgreSQL тоже serverless: после простоя первый запрос на секунду дольше;
- перед показом преподавателю открыть ссылку за полминуты — и всё летает.

## 1. Аккаунт и проверка доступа из РФ

1. Открыть https://app.koyeb.com — регистрация через GitHub (или
   Google/e-mail). Карта не запрашивается, план отображается как Free.
2. Если сайт из РФ не открывается — запасной вариант: `DEPLOY_AMVERA.md`
   (условно-бесплатный стартовый баланс).

## 2. Репозиторий

Koyeb собирает сервис из GitHub-репозитория, поэтому код должен быть на
origin. Порядок прежний: коммиты на `dev`, push `dev`, затем dev → main
через pull request; сервис в Koyeb указываем на `main`.

    git push origin dev

После влития PR `dev → main` push в `main` запускает пересборку в Koyeb
автоматически (шаг 7).

## 3. База данных

1. Панель https://app.koyeb.com → слева **Databases** → **Create Database**.
2. Имя `funds-db`, регион ближайший к Европе (Frankfurt/Paris), план **Free**;
   создание занимает около минуты.
3. На странице базы открыть **Connection Details** и скопировать готовую
   строку подключения вида

       postgres://<user>:<password>@<host>.koyeb.app:5432/<dbname>

   Спецсимволы пароля URL-кодируются (`@` → `%40`, `#` → `%23` и т.п.).
   Строку никуда не записывать — она пойдёт только в переменную окружения
   (шаг 4.5) и в команду сида (шаг 5).

## 4. Сервис приложения

1. **Create App** → источник **GitHub** → выбрать репозиторий, ветку `main`.
2. Builder: **Dockerfile** (файл в корне репозитория подхватится сам).
3. Instance type: **Free** (0.1 vCPU / 512 МБ — для лабы с запасом).
4. Порты: **8000**, тип **public** (HTTP). Наш CMD слушает `PORT` из
   окружения, поэтому менять число в поле порта Koyeb не нужно.
5. **Environment variables** → добавить:

       DATABASE_URL = postgres://<user>:<password>@<host>.koyeb.app:5432/<dbname>

6. Имя сервиса, например `funds-lab3` → **Deploy**. Прогресс — во вкладке
   **Logs**; готовность — статус Healthy.
7. Публичный адрес — в настройках домена сервиса:
   `https://funds-lab3-<org>.koyeb.app` (занести в отчёт).

## 5. Наполнение БД (один раз, с локальной машины)

Внешний доступ к базе Koyeb даёт из коробки (SSL уже в строке подключения;
если нет — добавить `?sslmode=require`). Из корня репозитория:

    backend/.venv/Scripts/python db/seed_amvera.py "postgres://<user>:<pass>@<host>.koyeb.app:5432/<dbname>"

Ожидаемый результат: `instruments = 18, price_snapshots = 558`.
Повторный запуск на непустой базе прерывается; `--force` пересоздаёт схему.
URL с паролем — только аргумент командной строки, в файлы не попадает.

## 6. Проверка

- `https://funds-lab3-<org>.koyeb.app/` — UI лабы: каталог, поиск, карточка
  инструмента, график цены;
- `.../docs` — Swagger с запросами Q1–Q5;
- `.../api/sectors/summary` — JSON агрегатов (значит, БД подключена).

## 7. Обновления

`git push` в `main` → Koyeb пересобирает и перезапускает сервис
автоматически, ручных действий нет.

## Откат/диагностика

- Сборка падает: вкладка Build в логах — чаще опечатка в `requirements.txt`
  или `Dockerfile`.
- Сервис жив, но страницы отдают ошибку БД: не задан или неверный
  `DATABASE_URL` — проверить URL-кодирование спецсимволов пароля.
- Первый запрос после долгого простоя медленный (1–5 секунд): это сон
  free-инстанса, не ошибка.
- База пустая: сид не запускали или запускали не на ту базу — сверить URL
  с `DATABASE_URL` сервиса.

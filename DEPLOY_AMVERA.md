# Публикация лабораторной №3 на Amvera Cloud

Ссылка для преподавателя: приложение на бесплатном домене `*.amvera.io` —
открывается из России без VPN. Старая версия на `*.chatgpt.site` недоступна
из РФ (гео-блок OpenAI), и к тому же была переписана на Worker+D1, а не
оригинальный FastAPI+PostgreSQL. Здесь публикуется настоящий `backend/`.

Состав деплоя:
- `amvera.yml` — конфигурация приложения Amvera (Python/pip, uvicorn, порт 8000);
- `db/seed_amvera.py` — разовое наполнение облачной БД:
  db/schema.sql → db/seed.sql → db/seed_history.sql;
- лаба целиком — `backend/`: FastAPI сам раздаёт UI (`backend/app/static`)
  и пять API-запросов Q1–Q5.

Правила прежние: пароли и URL с реквизитами в репозиторий не попадают;
push в GitHub публикацию на Amvera не запускает — публикация это push
в отдельный remote `amvera`.

## 1. Проект приложения

1. amvera.ru → создать проект «Приложение», окружение **Python**, имя,
   например `funds-lab3`.
2. Во вкладке «Домены» включить бесплатный домен `*.amvera.io`.
3. В репозитории проекта должен лежать наш `amvera.yml` из корня этой ветки.
   Если мастер Amvera создал на `master` свой файл настроек — заменить его
   содержимое нашим (ключевое: `containerPort` и порт в `command` совпадают).

## 2. База данных

1. На главной Amvera выбрать «PostgreSQL» → «Создать базу данных»;
   тариф не ниже «Начальный»; задать имя БД, пользователя и пароль
   (имя `postgres` зарезервировано).
2. В настройках ПРИЛОЖЕНИЯ добавить переменную окружения:

       DATABASE_URL=postgresql://<user>:<pass>@amvera-<логин>-cnpg-<проект-бд>-rw:5432/<имя-бд>

   Внутренний хост — из вкладки «Инфо» проекта БД. Спецсимволы пароля
   URL-кодируются (`@` → `%40` и т.п.). `backend/app/database.py` сам
   перепишет `postgresql://` в `postgresql+psycopg2://`.

## 3. Наполнение БД (один раз, с локальной машины)

Внешний доступ: создать в проекте БД доменное имя типа POSTGRES
(`<проект-бд>-<логин>.db-msk0.amvera.tech`), SSL обязателен.

    backend/.venv/Scripts/python db/seed_amvera.py "postgresql://<user>:<pass>@<проект-бд>-<логин>.db-msk0.amvera.tech:5432/<имя-бд>?sslmode=require"

Ожидаемый результат: `instruments = 18, price_snapshots = 558`
(проверено на локальной одноразовой базе). Повторный запуск на непустой
базе прерывается; перезалить данные: тот же вызов с `--force`.

## 4. Публикация кода

    git remote add amvera <адрес репозитория из вкладки «Репозиторий» проекта>
    git push amvera lab3:master

Сборка и старт — несколько минут; прогресс и ошибки — во вкладке «Логи»
(сборка + приложение).

## 5. Проверка

- `https://<проект>-<логин>.amvera.io/` — UI лабы: каталог, поиск, карточка
  инструмента, график цены;
- `.../docs` — Swagger с запросами Q1–Q5;
- `.../api/sectors/summary` — JSON агрегатов (значит, БД подключена).

## Стоимость

Приложение и БД тарифируются отдельно; у новых аккаунтов есть стартовый
баланс — его обычно хватает на время приёмки. Актуальные цены см. на
amvera.ru при создании проектов.

## Откат/диагностика

- Приложение не стартует: логи → чаще всего не задан `DATABASE_URL` или
  не совпал порт (`containerPort` и `command`).
- Ошибка подключения к БД из интернета: не создан домен POSTGRES или
  в URL нет `?sslmode=require`.

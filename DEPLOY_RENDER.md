# Публикация лабораторной №3 — Render (приложение) + Aiven (PostgreSQL)

Полностью бесплатная связка навсегда, без банковской карты:

- **Render free** — веб-сервис: Docker из GitHub, 512 МБ RAM, постоянный
  домен `*.onrender.com`. Спит после ~15 минут без трафика, холодный старт
  30–60 секунд. Сервисы free-плана не имеют срока действия.
- **Aiven free** — PostgreSQL: ~1 ГБ, без срока действия, без карты,
  ежедневные бэкапы, публичная строка подключения с sslmode=require.

Почему база не на Render: бесплатная БД Render **истекает через 30 дней**
после создания (14 дней грейс-периода — и удаление с данными). Это
«условно-бесплатно», от чего уходим. Приложение и БД в этой связке — в двух
аккаунтах, оба открываются из РФ (проверено 2026-11-03: render.com,
console.aiven.io и зона *.onrender.com отвечают с российского IP и точек
check-host.net в РФ).

Код приложения и образ не менялись:
- `Dockerfile` подходит как есть: Render передаёт порт сервису в переменной
  `PORT`, наш CMD слушает `${PORT:-8000}`;
- `render.yaml` — blueprint: Render сам создаёт сервис по этому файлу
  (Docker, free, Frankfurt, автодеплой из main), остаётся вставить
  `DATABASE_URL`;
- `backend/app/database.py` сам приводит `postgres://`/`postgresql://` к
  `postgresql+psycopg2://`, `pool_pre_ping=True` стабилизирует соединения;
- `db/seed_amvera.py` универсален — URL подключения передаётся аргументом.

## 1. Аккаунты и проверка доступа из РФ

1. https://render.com → **Sign up with GitHub**. Карта не требуется.
2. https://aiven.io → **Get started for free** → регистрация
   (GitHub/Google/e-mail). Карта не требуется.
3. Если что-то из этого из РФ не откроется — запасные варианты в конце.

## 2. База данных (Aiven)

1. https://console.aiven.io → **Create service** → **PostgreSQL**.
2. ВАЖНО — не взять план по умолчанию: мастер подставляет платный
   **Developer-1** с триальными кредитами ($50, но триал длится 30 дней —
   потом сервис выключат до добавления оплаты). Нажать **Customize plan
   and cloud** под карточкой плана и выбрать план **Free** ($0: 1 CPU /
   1 ГБ RAM / 1 ГБ storage; по прайсу Aiven «Free plans do not have any
   time limitations»). На Free-плане облако/регион назначается
   автоматически — выбрать нельзя, для лабы нормально. Если плана Free в
   диалоге нет — начинать создание через https://aiven.io/free-tier.
   Имя сервиса `funds-db`.
3. Дождаться статуса **Running** (несколько минут).
4. Вкладка **Overview** → блок **Connection information** → **Service URL**
   вида

       postgres://<user>:<password>@<host>-<project>.aivencloud.com:<port>/<dbname>?sslmode=require

   Это и `DATABASE_URL` для приложения, и URL для сида. Спецсимволы пароля
   URL-кодируются (`@` → `%40`, `#` → `%23` и т.п.). Строку с паролем в
   файлы не записывать.
5. На Free-плане Aiven один сервис на аккаунт — для лабы этого достаточно.

## 3. Веб-сервис (Render, по blueprint)

Предварительно: PR `dev → main` влит и запушен — Render деплоит из `main`.

1. Render Dashboard → **New +** → **Blueprint** → выбрать репозиторий
   (`igrgrya/web_app`), ветку **main**.
2. Render прочитает `render.yaml` из корня и покажет, что создаст: сервис
   `funds-lab3` (Docker, free, Frankfurt, автодеплой из main).
3. В окне применения запросит значение переменной `DATABASE_URL` — вставить
   **Service URL из шага 2** (строку подключения Aiven целиком, вместе с
   `?sslmode=require`).
4. **Apply** → сборка и старт — несколько минут; готовность — статус
   **Live**; ошибки — вкладка **Events/Logs**.
5. Адрес в шапке сервиса: `https://funds-lab3.onrender.com` (постоянный,
   занести в отчёт).

Ручной путь вместо blueprint (если что-то не так с render.yaml):
**New + → Web Service** → репозиторий, ветка main → Runtime **Docker** →
Region **Frankfurt** → Instance **Free** → переменная `DATABASE_URL` →
**Create Web Service**.

## 4. Наполнение БД (один раз, с локальной машины)

Из корня репозитория, URL — Service URL из шага 2:

    backend/.venv/Scripts/python db/seed_amvera.py "postgres://<user>:<pass>@<host>.aivencloud.com:<port>/<dbname>?sslmode=require"

Ожидаемый результат: `instruments = 18, price_snapshots = 558`.
Повторный запуск на непустой базе прерывается; `--force` пересоздаёт схему.
URL с паролем — только аргумент командной строки, в файлы не попадает.

## 5. Проверка

- `https://funds-lab3.onrender.com/` — UI лабы: каталог, поиск, карточка
  инструмента, график цены;
- `.../docs` — Swagger с запросами Q1–Q5;
- `.../api/sectors/summary` — JSON агрегатов (значит, БД подключена).

## 6. Обновления

`git push` в `main` → Render пересобирает и перезапускает сервис
автоматически (`autoDeployTrigger: commit`). Бесплатный план включает
500 минут сборки в месяц — для лабы хватает с запасом.

## Особенности free-планов (норма для всех бесплатных тарифов)

- Сервис Render засыпает после ~15 минут без трафика; первый посетитель
  ждёт 30–60 секунд. **Перед показом преподавателю открыть ссылку за
  1–2 минуты.**
- БД Aiven не засыпает и не истекает; лимиты Free (~1 ГБ) для лабы
  избыточны.
- Файловая система сервиса временная: загруженные файлы теряются при
  рестарте — лаба файлы не хранит, не критично.

## Запасные варианты

- Aiven недоступен при регистрации → бесплатная БД Render (**создать
  прямо перед защитой**: живёт 30 дней; render.yaml при этом не
  используется, БД и сервис создаются вручную, Internal URL в
  DATABASE_URL) или Supabase/Neon free (проект Supabase пауза-ится после
  7 дней неактивности — будится вручную).
- Render недоступен из РФ или требует карту → **alwaysdata** (100 МБ,
  Python и PostgreSQL прямо в бесплатном аккаунте, навсегда, без карты —
  всё в одном месте, но диск впритык) — скажите ZCode, подготовит пакет.

## Откат/диагностика

- Blueprint не применился: проверить, что `render.yaml` в корне ветки
  main и синтаксис не правился; либо применить ручной путь из шага 3.
- Сборка падает: вкладка Logs (фаза Build) — чаще опечатка в
  `requirements.txt` или `Dockerfile`.
- Сервис Live, но страницы отдают ошибку БД: `DATABASE_URL` не задан или
  не содержит `?sslmode=require` (Aiven требует SSL); сверить строку с
  Connection information в Aiven.
- 502/«No open ports»: сервис деплоится не из свежего `Dockerfile` (CMD
  должен слушать `${PORT:-8000}`), либо указан не тот бранч.
- Первый запрос после долгого простоя крутится 30–60 секунд: это сон
  free-инстанса, не ошибка — повторить запрос.
- База пустая: сид не запускали или запускали не на ту базу — сверить URL
  сида с `DATABASE_URL` сервиса.

# Публикация лабораторной №3 на Render — полностью бесплатный хостинг

Актуальный вариант после закрытия free-тарифа Koyeb (в феврале 2026 Koyeb
поглощён Mistral AI, новым аккаунтам осталась только регистрация на платные
планы — консоль показывает объявление без меню создания сервисов).

Render free-план (проверено по render.com/pricing в ноябре 2026):
- веб-сервис $0: 512 МБ RAM, спит после ~15 минут без трафика, холодный
  старт 30–60 секунд;
- PostgreSQL $0: 1 ГБ SSD, 256 МБ RAM, до 100 соединений;
- регистрация через GitHub без банковской карты, постоянный домен
  `*.onrender.com`, приложение и БД — в одном аккаунте.

Код приложения и образ не менялись:
- `Dockerfile` подходит как есть: Render передаёт порт сервису в переменной
  `PORT`, а наш CMD слушает `${PORT:-8000}`;
- `backend/app/database.py` сам приводит `postgres://`/`postgresql://` к
  `postgresql+psycopg2://`, `pool_pre_ping=True` стабилизирует соединения;
- `db/seed_amvera.py` универсален — URL подключения передаётся аргументом.

## 1. Аккаунт и проверка доступа из РФ

1. Открыть https://render.com → **Sign up with GitHub**. Карта не требуется
   (Render иногда просит карту «в некоторых сценариях» для защиты от абьюза —
   если карту требуют жёстко уже на регистрации free-тарифа, остановиться и
   перейти к запасным вариантам, см. конец файла).
2. Если сайт из РФ не открывается — тоже запасные варианты.

## 2. База данных PostgreSQL

1. Dashboard → **New +** → **Postgres**.
2. Имя `funds-db`, регион **Frankfurt**, план **Free** (1 ГБ).
3. После создания открыть блок **Connections** — там два URL:
   - **Internal Database URL** — для приложения (шаг 3), работает только
     внутри сети Render;
   - **External Database URL** — для наполнения с локальной машины (шаг 4),
     обычно уже содержит `?sslmode=require`.
4. Проверить в панели, что у базы нет баннера о сроке жизни: у старого
   бесплатного Postgres Render (до 2022) база удалялась через 30–90 дней.
   Если баннер про удаление появится — перенести данные в Aiven free
   (aiven.io, Postgres без карты и без срока действия, ~1 ГБ), схема та же.

## 3. Веб-сервис

1. **New +** → **Web Service** → подключить GitHub-репозиторий
   (`igrgrya/web_app`), ветка **main**.
2. Runtime: **Docker** — Dockerfile в корне репозитория подхватится сам.
3. Region: **Frankfurt** — тот же, что у БД (иначе Internal URL не сработает).
4. Instance Type: **Free** (0.1 CPU / 512 МБ — для лабы с запасом).
5. **Environment variables** → добавить:

       DATABASE_URL = <Internal Database URL из шага 2>

6. Имя сервиса, например `funds-lab3` → **Create Web Service**. Сборка и
   старт — несколько минут; прогресс и ошибки — вкладка **Events/Logs**;
   готовность — статус **Live**.
7. Адрес сервиса показывается в шапке: `https://funds-lab3.onrender.com`
   (постоянный, занести в отчёт).

## 4. Наполнение БД (один раз, с локальной машины)

Из корня репозитория, URL — External Database URL из шага 2:

    backend/.venv/Scripts/python db/seed_amvera.py "postgres://<user>:<pass>@dpg-<...>.frankfurt-postgres.render.com:5432/<dbname>?sslmode=require"

Ожидаемый результат: `instruments = 18, price_snapshots = 558`.
Повторный запуск на непустой базе прерывается; `--force` пересоздаёт схему.
URL с паролем — только аргумент командной строки, в файлы не попадает.

## 5. Проверка

- `https://<имя-сервиса>.onrender.com/` — UI лабы: каталог, поиск, карточка
  инструмента, график цены;
- `.../docs` — Swagger с запросами Q1–Q5;
- `.../api/sectors/summary` — JSON агрегатов (значит, БД подключена).

## 6. Обновления

`git push` в `main` → Render пересобирает и перезапускает сервис
автоматически. Бесплатный план включает 500 минут сборки в месяц — для
лабы хватает с запасом.

## Особенности free-плана (норма для всех бесплатных тарифов)

- Сервис засыпает после ~15 минут без трафика; первый посетитель ждёт
  30–60 секунд. **Перед показом преподавателю открыть ссылку за 1–2 минуты**,
  при необходимости обновить страницу после загрузки.
- БД не засыпает; лимиты free-БД (1 ГБ, 100 соединений) для лабы избыточны.
- При подозрении на абьюз Render может приостановить сервис — для учебной
  нагрузки (единичные показы) это не актуально.

## Запасные варианты, если Render недоступен из РФ или требует карту

- **alwaysdata** (alwaysdata.com): 100 МБ, Python и PostgreSQL прямо в
  бесплатном аккаунте, бесплатно навсегда, без карты — всё в одном месте,
  но диск впритык;
- **Aiven free Postgres** (aiven.io, без карты и срока действия) + любой
  доступный бесплатный Python-хостинг;
- **Vercel Hobby + Neon free** (serverless-вариант, больше возни с адаптацией).

## Откат/диагностика

- Сборка падает: вкладка Logs (фаза Build) — чаще опечатка в
  `requirements.txt` или `Dockerfile`.
- Сервис Live, но страницы отдают ошибку БД: проверить `DATABASE_URL` —
  должен быть **Internal** Database URL того же региона, что и сервис.
- 502/«No open ports»: сервис деплоится не из свежего Dockerfile (CMD
  должен слушать `${PORT:-8000}`), либо при создании указан не тот бранч.
- Первый запрос после долгого простоя крутится 30–60 секунд: это сон
  free-инстанса, не ошибка — повторить запрос.
- База пустая: сид не запускали или запускали не на ту базу — сверить URL
  с `DATABASE_URL` сервиса (сид делается по External URL).
